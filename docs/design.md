# Как устроен сервис

Сервис хранит сведения об угрозах и позволяет найти запись по MD5 файла. Через API можно создать запись, получить её или полностью заменить изменяемые поля. Команды запуска и примеры запросов находятся в [README](../README.md); здесь описаны устройство проекта и причины основных решений.

## Обработка запроса

HTTP-обработчик сначала проверяет доступ и формат запроса. Затем данные проходят проверку полей, и только после этого сервис обращается к базе. Поэтому ошибка в JSON или значении поля не приводит к частичному обновлению записи.

Код разделён по обязанностям:

| Пакет | За что отвечает |
| --- | --- |
| `cmd/server` | Читает настройки, открывает БД, запускает HTTP или HTTPS и обрабатывает завершение процесса. |
| `internal/config` | Проверяет переменные окружения до запуска сервера. |
| `internal/httpapi` | Принимает запросы, проверяет токен и лимит нагрузки, преобразует результаты в HTTP-ответы. |
| `internal/threat` | Проверяет поля угрозы и приводит их к единому виду. |
| `internal/store` | Создаёт схему SQLite, читает и сохраняет записи. |
| `internal/api` | Содержит модели запросов и ответов, сгенерированные из OpenAPI. |

HTTP-слой обращается к хранилищу через интерфейс `Repository`. Правила проверки угрозы не зависят от HTTP и SQLite, поэтому их можно тестировать отдельно. Для HTTP используется стандартный пакет `net/http`: его возможностей достаточно для трёх операций и проверки доступности.

## Контракт и данные

Контракт описан в [api/openapi.yaml](../api/openapi.yaml). Из него `oapi-codegen` генерирует Go-структуры запросов и ответов. Версия генератора закреплена в `go.mod`, а результат генерации включён в проект. Обработчики и проверка полей написаны вручную; тесты дополнительно сверяют ответы с OpenAPI.

В исходной модели обязательны MD5 и название. Описание, категория, уровень опасности и время обнаружения добавлены как необязательные поля, чтобы минимальный запрос с `md5` и `name` оставался допустимым. Даты создания и изменения назначает сервер в UTC.

MD5 хранится в нижнем регистре: хеши, отличающиеся регистром букв, относятся к одной записи. `PUT` полностью заменяет изменяемые поля. Например, запрос только с новым `name` также очищает описание, сбрасывает категорию и уровень опасности в `unknown` и убирает время обнаружения. MD5 и дата создания сохраняются. Если записи нет, возвращается `404`.

## Почему SQLite

SQLite позволяет запустить сервис и интеграционные тесты без отдельного сервера БД. Все данные находятся в файле, путь к которому задаётся через `DB_PATH`.

При запуске сервис проверяет версию схемы через `PRAGMA user_version`. Начальная миграция выполняется в транзакции. Если версия схемы неизвестна приложению, запуск прекращается с ошибкой.

В базе MD5 является первичным ключом. Два одновременных запроса на создание одного MD5 не смогут сохранить дубликаты: один завершится успешно, остальные получат `409`. Создание и замена выполняются одним SQL-запросом с `RETURNING`, который сразу возвращает сохранённую запись. Значения пользователя передаются параметрами SQL.

## Доступ и ограничения нагрузки

Для всех операций с угрозами нужен один общий Bearer-токен. Его владельцы имеют одинаковые права чтения и записи. Токен проверяется при запуске, а при запросе сравниваются SHA-256-дайджесты за постоянное время. Токены и тела запросов не попадают в логи.

Лимит запросов также общий для процесса. Он учитывает в том числе обращения с неверным токеном; при превышении сервер отвечает `429` с заголовком `Retry-After`. Проверка `/healthz` доступна без токена и не расходует этот лимит.

Тело запроса ограничено 16 KiB. Сервер принимает один JSON-объект и отклоняет неизвестные поля, повторные ключи, неверный регистр имён и `null`. Для HTTP заданы таймауты, а контекст запроса с дедлайном передаётся в SQL-операции. Подробности внутренних ошибок остаются в серверных логах.

HTTPS включается сертификатом и ключом из переменных окружения; минимальная версия TLS — 1.2. При получении SIGINT или SIGTERM сервер прекращает принимать новые соединения, ждёт текущие запросы до десяти секунд и затем закрывает БД.

## Границы решения

Приложение рассчитано на один экземпляр сервиса. В API предусмотрены создание, чтение и замена записи; список угроз и удаление не входят в текущий контракт. При одновременных заменах одной записи сохраняется результат последнего выполненного UPDATE.
